# Metric sources and interpretation

The [BigCodec paper, evaluation setup and Table I](https://arxiv.org/html/2409.05377v1) reports PESQ-NB, PESQ-WB, STOI, mel cepstral distortion, speaker similarity and MUSHRA. Its main evaluation uses 2,620 clean LibriSpeech utterances at 16 kHz. BigCodec reports PESQ-WB 2.68 and STOI 0.93 on that dataset. Those numbers are not thresholds for the eight noisy recordings here, and CPU-reference implementation agreement is a different comparison. The paper also uses spectral reconstruction loss rather than time-domain reconstruction loss.

The [pinned upstream training code](https://github.com/Aria-K-Alethia/BigCodec/blob/09845ab1f5bc7a3d1589c16de820ef15bc2afefe/lightning_module.py) contains empty `validation_step` and `test_step` methods. This report implements the stated metrics with the identified packages; it does not claim to reproduce an upstream scoring script or the paper dataset.

[STOI's author description and reference code](https://ceestaal.nl/code/) define an intrusive intelligibility measure comparing clean and degraded speech. Our [pystoi implementation](https://github.com/mpariente/pystoi) is version 0.4.1. Standard STOI is reported alongside optional ESTOI in JSON. These scores are correlations of processed speech representations, not percentages of words understood. A noisy or codec-reconstructed reference is useful for agreement diagnostics but cannot substantiate clean-reference intelligibility claims.

[PESQ's Python wrapper](https://github.com/ludlows/PESQ), version 0.0.4, computes narrowband and wideband MOS-LQO scores. We use both at 16 kHz. Its normal internal level and delay processing remains part of PESQ; no additional alignment or amplitude fitting is performed. The [ITU P.862 recommendation page](https://www.itu.int/rec/t-rec-p.862) records that the P.862 family was withdrawn in January 2024. PESQ is used here because it is one of the published BigCodec criteria, not because it is the current ITU recommendation.

Magnitude spectral convergence uses the same normalized Frobenius-norm form as the [Parallel WaveGAN reference implementation](https://github.com/kan-bayashi/ParallelWaveGAN/blob/master/parallel_wavegan/losses/stft_loss.py). Our diagnostic explicitly uses periodic Hann windows of 512, 1,024 and 2,048 samples, quarter-window hops, zero padding and one-sided spectra. It is not an exact reproduction of that project's window settings or BigCodec's mel loss. Magnitude spectra ignore phase: an inverted waveform has 200% raw relative L2 but zero magnitude error. A smaller spectral percentage therefore does not satisfy a waveform-error target.

[ViSQOL's official documentation](https://github.com/google/visqol) describes a speech mode at 16 kHz and expects a clean reference of equal or higher quality than the degraded signal. ViSQOL is not installed in this environment, and no ViSQOL scores are reported. MCD, speaker embeddings and listening-test results are also not reported.

Use the raw waveform and token comparisons to debug numerical implementation, and inspect PESQ/STOI plus spectral differences as complementary measures of codec fidelity. For listening-quality claims or acceptance thresholds, use clean speech references and listening tests. None of the reported metrics automatically certifies the requested waveform error below 10%.
